## 📌 Sobre o projeto

Este repositório **não é um sistema, um app ou um site funcionando**. É uma brincadeira séria: usar a linguagem do desenvolvimento de software (commits, versões, bugs, roadmap, build) para contar a história da nossa turma no começo da graduação.

O produto que estamos construindo somos nós mesmos: pessoas aprendendo a programar, a pensar como engenheiras e engenheiros de software e a trabalhar em equipe.

Também é um exercício prático de **Markdown** e **GitHub**, duas ferramentas que vamos usar durante todo o curso.

## 📚 Tecnologias em aprendizado

Nenhuma dessas tecnologias está "dominada". Estão todas **em aprendizado**, e isso é o esperado para o 1º semestre.

- **Lógica de programação:** a base de tudo. É aprender a quebrar um problema em passos claros, usando variáveis, condições e repetições, antes mesmo de escolher a linguagem.
- **HTML:** a estrutura de uma página web. Títulos, parágrafos, listas, links e imagens.
- **CSS:** a aparência. Cores, fontes, espaçamentos e organização visual do que o HTML construiu.
- **Java:** linguagem de programação muito usada no mercado, que nos apresenta ideias como tipos de dados, classes e objetos.
- **SQL:** a linguagem para conversar com bancos de dados: guardar, consultar e organizar informações.
- **Linguagem C:** uma linguagem mais próxima do funcionamento do computador, que nos ensina o que acontece "por baixo do capô".

## 🐛 Bugs conhecidos

Lista não oficial de problemas que quase todo mundo já encontrou no começo da jornada.

- **#001 · O ponto e vírgula fantasma**
  O código parece perfeito. O compilador discorda. Status: reproduzível todos os dias.

- **#002 · Corrige um erro, aparecem três**
  Comportamento inesperado: resolver um problema gera novos problemas, sempre com nomes mais criativos. Status: aberto (como todo desenvolvedor sabe).

- **#003 · "Na minha máquina funciona"**
  Frase clássica. Funciona no computador de quem escreveu e em nenhum outro lugar. Status: não é bug, é mistério.

- **#004 · `=` ou `==`?**
  Uma diferença de um símbolo, uma tarde inteira de investigação.

- **#005 · A tag que nunca foi fechada**
  No HTML, uma única tag esquecida e a página inteira muda de forma. Status: caça ao tesouro.

- **#006 · O CSS que não muda nada**
  Você altera a cor, salva, recarrega e nada acontece. Possíveis causas: seletor errado, arquivo errado ou… o arquivo não foi salvo.

- **#007 · Sono às 21h**
  Nível de energia abaixo do esperado no período noturno. Mitigação: café, colegas e boa vontade.

- **#008 · Funcionou, mas ninguém sabe por quê**
  O código roda. Tecnicamente é um sucesso. Emocionalmente, é um alerta.

> 💡 **Importante:** todo bug aqui é um aprendizado disfarçado. Se você já passou por algum deles, parabéns: você está programando de verdade.

## 🤝 Como contribuir

Qualquer pessoa da turma pode contribuir, **sabendo Git ou não**.

### Opção 1 · Sem conhecer o GitHub
Envie sua sugestão para o grupo da turma no WhatsApp. 
Pode ser:
- um bug conhecido que você já enfrentou;
- uma tecnologia ou objetivo para o roadmap;
- uma correção de texto ou uma ideia nova.

Alguém da turma coloca no repositório pra você.

### Opção 2 · Pelo GitHub, direto no navegador
1. Abra o arquivo `README.md` neste repositório.
2. Clique no ícone de lápis (✏️) para editar.
3. Faça a sua alteração e use a aba **Preview** para conferir.
4. Escreva uma mensagem curta explicando o que mudou e confirme.
5. Se você não for colaborador do repositório, o GitHub cria uma proposta de alteração (*pull request*) para a pessoa responsável revisar antes de entrar.

### Combinados da turma
- Humor leve e respeitoso. Piada boa ri *com* a turma, nunca *de* alguém.
- Não cite nomes de pessoas, professores ou da faculdade sem autorização.
- Não publique dados pessoais.
- Na dúvida, pergunte antes de alterar.
